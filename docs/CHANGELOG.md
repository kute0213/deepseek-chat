# 更新日志

## 2026-11-27（结构自愈，修复多操作 500）

- 新增 `app/Support/Schema.php`：首次数据库连接时按 `schema.sql` 补齐缺失的表，并检查 / 追加历史上新增的列（`users` 的 API Key 字段、`sessions` 的统计与置顶字段、`auth_tokens` 的 CSRF 字段、`files` / `share_links` 等）。老站点覆盖代码即可升级，不再因缺表缺列导致登录、会话、上传聊天记录等大量操作 500。
- `Database::pdo()` 在建立连接后、开启事务前执行结构自愈；版本标记写入 `uploads/config/schema.version`，后续请求只读标记，不再重复 DDL。
- 修复大聊天记录导入：`Snowflake::nextBatch()` 不再把请求数量截断为 4000，避免消息数超过 4000 时 ID 池不足导致数组越界 500。
- 错误日志补充请求方法与 URI，便于定位具体操作。

## 2026-11-26（修复删除用户 500、管理后台取消折叠）

### 修复删除用户后报服务器内部错误

- 根因：删除用户事务内调用了建表语句。MySQL 的 DDL 会隐式提交当前事务，导致后续操作脱离事务；最终 `commit()` 找不到活跃事务抛出异常，表现为「提示 500，但刷新后用户已删除」。
- 修复：新增 `SessionStore::prepareArchive()`、`ShareService::prepare()`，在事务开始前预建用量归档表与分享表；`ensureArchive()` / `ensureTable()` 在事务中不再执行 DDL。
- 同样修复历史导入事务中的相同隐患。

### 管理后台

- 取消管理后台侧边栏的折叠 / 展开功能，恢复固定宽度标签页与文字导航，保留无刷新页面切换。
