# Development Guidelines

## 1. Architecture

- Backend: PHP 8.1+ with MySQL 5.7+ / MariaDB 10.4+. The root `index.php` is the entry point (SPA output, API routing, and dispatch for `/install`, `/docs`, `/404`).
- Frontend: the official deepseek-demo (React + TypeScript + rspack). Source lives in `frontend/`; the build outputs `index.html` and `static/` at the project root and is served same-origin with the PHP API.
- Admin console: server-rendered PHP. Entry `admin/index.php`, pages in `admin/pages/`, shared shell `layout.php`.
- Runtime data: `uploads/` (config, logs, attachments, import staging). Never commit it.
- Shared server code: `app/Support/` (config, database, auth, snowflake IDs, request/response, language files); business logic in `app/Services/`; endpoints in `app/Controllers/`.

## 2. How the frontend and PHP work together

1. `index.php` reads the built `index.html`, injects the site name and `window.__SITE__`, then outputs it. The default index must therefore be `index.php`.
2. All business requests use same-origin `/api/*`. If rewrite rules are missing and the API returns 404, the client falls back to `/index.php?_r=/api/...` and must preserve all query parameters.
3. The browser only holds site info and a masked API key. Every DeepSeek request is proxied by PHP; the key never reaches the browser.
4. Use the official components and theme tokens for controls, dialogs, and colors. Do not invent another button or dialog style.

## 3. Site name and copy

- Server-rendered pages read from `app/Support/Lang.php`; strings live in `app/lang/zh-CN.php` and `app/lang/en-US.php`.
- When changing the site name, also update the language files, `site_settings` defaults, installer defaults, front-end `appName`, and the static 404 page.
- Never hard-code the site name across pages.

## 4. Visual and component rules

- Server-rendered pages (admin, installer, 404, docs shell) all reference `assets/ui.css`. Do not duplicate `:root` tokens or control styles.
- Official values:
  - Brand blue `#3964fe`, hover `#5686fe`; dark-mode brand `#5686fe`.
  - Pill radius `4096px`; primary controls 40px high; admin buttons 36px.
  - Dialog radius 24px, overlay `rgba(0,0,0,.36)` with `blur(2px)`, content width 380px, padding `22px 24px`.
  - Transitions use `0.2s cubic-bezier(0.4, 0, 0.2, 1)`.
- Support both light and dark modes (`prefers-color-scheme` plus the explicit `data-theme` preference).
- Delete unused classes, styles, and assets instead of keeping "maybe later" code.

## 5. Chat data and pagination

- Message page size is 20; the session list also uses 20 per page.
- Opening a session loads the latest page first. Scrolling to the top loads an earlier page and shows a loading indicator; hide it when no earlier messages exist.
- When earlier messages are prepended, correct the scroll position so the reading position does not jump. Use the same logic whether loading was triggered by the list or the right-side navigator.
- The right-side navigator has one bar per user prompt: hover to preview on desktop, click to jump, and smooth-scroll the preview to center the active item. The preview list also loads earlier messages when scrolled to the top.

## 6. Import and export

- Export must fetch all sessions and full messages from the server, then build an official-format ZIP locally with a progress percentage.
- Import replaces all data. Confirm before importing and keep existing data if the import fails.
- Keep the archive format compatible with the official one, including older archives without an index.

## 7. Security

- Sessions use HttpOnly cookies; the database stores only a token digest.
- Every write API validates `Origin` and `X-CSRF-Token`.
- Sign-in, registration, and admin login require a captcha; answers are hashed, single-use, and expire after 5 minutes.
- API keys are stored in plain text as the product requires, used only server-side, and shown to the browser as a 4-character mask.
- Production must use HTTPS and deny direct access to `app/`, `uploads/`, `docs/`, `frontend/`, `scripts/`, and `.git`.

## 8. Docs and commits

- Update on every change: root `README.md`, `docs/CHANGELOG.md`, and any affected implementation docs.
- `docs/README.md` mirrors the root README; keep them in sync.
- The author and committer must be the project owner only (`kute0213 <3846415473@qq.com>`); automated agent accounts must not appear.
- Run before committing:

```bash
find app admin -name '*.php' -print0 | xargs -0 -n1 php -l
cd frontend && pnpm run type && pnpm run lint && pnpm run build
```

- Never commit `scripts/`, `uploads/`, `frontend/node_modules/`, or `.pnpm-store/`.
